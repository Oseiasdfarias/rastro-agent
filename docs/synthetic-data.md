# Synthetic data

Everything is generated by `src/synthdata` with a fixed seed (`python -m synthdata --seed 7`).
The company, customers and products are fictional. Table and field names follow common SAP
tables so the queries look like the real thing; no real SAP data or system is involved.

| Table | Rows (seed 7) | Content |
|---|---|---|
| KNA1 | 40 | customers |
| MARA | 12 | rubber parts (seals, mounts, profiles, hoses) |
| EQUI | 6 | 4 molding presses, 2 extruders |
| AFKO / AFPO | 2,184 | production orders, one batch (CHARG) per shift |
| VBAK / VBAP, LIKP / LIPS | 2,184 each | sales orders and deliveries, one batch per delivery |
| QMEL | ~ 150 | maintenance notes, free text in shop-floor Portuguese |
| AUFK | ~ 85 | maintenance orders: PM02 preventive, PM01 corrective |
| crm_account / crm_case | 40 / 40 | CRM accounts and complaints |

## Planted failures

8 failure episodes, each with an equipment, a failure mode (`bearing_wear`, `heater_drift`,
`mold_wear`, `misalignment`, `sensor_fault`) and a window of 7 to 21 days. Inside the window
there are 2 to 4 maintenance notes that start vague ("ruido anormal lado acion.") and get
clearer, and one corrective order (PM01) at the end.

Routine records exist on every equipment all the time (PM02 every 14 days, cleaning, setup),
so "there was maintenance" is not a signal by itself.

## Evaluation cases

- 30 complaints about batches produced inside a failure window. Answer: `factory_cause`, the
  equipment and the failure mode.
- 10 complaints about batches far from any window, with text about transport, storage or
  use. Answer: `no_factory_cause`.
- 9 of the 30 have the delivery number removed (6) or mistyped (3). Only cases where customer +
  material in the last 90 days still lead to a single suspect batch are changed.

The answers are stored in `eval_truth`. No tool reads that table.
